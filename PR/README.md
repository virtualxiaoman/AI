# PR：论文复现工作区

`PR` 是 **Paper Reproduction** 的缩写。该目录用于存放独立论文的复现项目；当前仅提供统一的目录约定，不包含任何特定论文的实现。

## 顶层结构

```text
PR/
├── README.md                 # 本目录的结构与使用约定
├── docs/                     # 跨论文的复现规范、公共说明
├── papers/                   # 各篇论文的独立复现项目
└── _template/                # 新建论文项目时复制的目录模板
```

## 单篇论文的标准结构

在 `papers/` 下为每篇论文创建一个独立目录。目录名应使用简短、稳定、可辨识的论文缩写（建议全小写、连字符分隔），例如 `resnet`、`vit` 或 `ddpm`。

```text
papers/<paper-id>/
├── README.md                 # 论文信息、目标、复现结论与运行说明
├── assets/                   # README 使用的小型图片、图表等静态资源
├── configs/                  # 实验配置文件；每次可复现实验应对应明确配置
├── data/                     # 仅放数据说明、下载脚本或软链接；不提交大规模原始数据
├── docs/                     # 公式推导、阅读笔记、实现决策与问题记录
├── notebooks/                # 仅用于探索、可视化和分析，不承载正式训练流程
├── outputs/                  # 日志、检查点、预测与生成结果；默认不提交大文件
├── scripts/                  # 训练、评估、数据准备等可执行入口
├── src/                      # 可复用的正式实现代码
└── tests/                    # 单元测试、回归测试与最小可运行验证
```

`_template/` 与上述单篇论文结构保持一致。开始新的复现时，复制它到 `papers/<paper-id>/`，再补充该论文专属内容。

## 约定

1. **一篇论文一个目录**：不得将不同论文的模型、实验输出或配置混放。
2. **README 先行**：每个论文目录的 `README.md` 至少记录论文标题、链接/版本、复现范围、环境、数据来源、运行命令和与原文的结果对比。
3. **配置可追溯**：训练与评估的关键超参数必须写入 `configs/`；脚本不应依赖未记录的默认参数。
4. **代码与产物分离**：实现放在 `src/`，运行入口放在 `scripts/`，实验产物放在 `outputs/`。不要将检查点、数据集或大日志提交到 Git。
5. **数据不入库**：`data/` 只维护数据获取方式、预处理说明和必要的小型元数据；大型数据集统一使用仓库根目录的 `Datasets/` 或外部存储。
6. **结果可验证**：每项关键结论应保留对应配置、随机种子、运行命令和评价指标；必要时在 `tests/` 中提供最小验证。
7. **共享内容克制复用**：跨论文稳定且通用的工具或规范放在 `PR/docs/`；论文专属逻辑必须留在各自目录中。

## 命名建议

- 论文目录：`<paper-id>`，例如 `bert`、`clip`、`sam`。
- 配置文件：`<任务>-<模型>-<规模>.yaml`，例如 `cifar10-resnet18-base.yaml`。
- 输出实验目录：`<日期>-<配置名>-<随机种子>`，例如 `20260923-cifar10-resnet18-base-s42`。
- 不确定论文缩写时，优先选择论文标题中最有辨识度的首字母缩写，并在该论文的 `README.md` 写明全称。
